# Plan: Design Documentation for "SailAge" (Uncharted Waters 2-like Game)

Produce a complete set of English design documents in `docs/`, optimized for
AI-assisted ("vibe") implementation in Godot 4. No game code is written under
this plan — documentation only.

## Locked Decisions

| Area | Decision |
|---|---|
| Platform / engine | Godot 4.x + GDScript, 2D, desktop-first |
| Game scope | Phased full UW2 clone: Phase 1 sailing+trade, Phase 2 combat+duels, Phase 3 quests/discovery/titles/piracy/tournaments |
| Doc language | English (all docs) |
| Game language | Chinese + English via data files — every game-content string is a `{"zh","en"}` pair (not Godot `.po`) |
| Doc layout | Overview + per-system docs + per-phase task backlog (`IMPLEMENT-PhaseN.md`) |
| Sailing model | **Free-sail tile grid** (UW2-authentic): large tile-grid world map, ship moves 8-directionally, land tiles block movement. Godot TileMap-backed |
| Map authoring | Map data as **ASCII-art grid text files** under `data/maps/` with a legend (`~` sea, `#` land, port index markers) — agent-editable without Godot editor |
| Combat model | **Turn-based grid-lite** tactical battles (Phase 2): square grid, alternating turns, move + 1 action (cannon/ram/board) |
| Protagonist | **Nationality choice at new game** (Portugal/Spain/England/Holland/Ottoman/Italy → start port + starting reputation); no scripted storylines; Phase 3 quests serve the single character |
| World map | Phased: Phase 1 = Mediterranean + Western Europe (exactly 30 ports, list below); Phase 3 = full world |
| Crew sim (P1) | Hire/fire at taverns, daily wage, provisions/water consumed per crew per day, morale from provisions level + days at sea, mutiny/desertion event at low morale |
| Game over (P1) | **Sea-death only** (starvation/scurvy/ship sunk). No bankruptcy game-over; ports offer a harbor-relief fallback (odd-job income) so softlock is impossible |
| Players | Single-player, offline only. No multiplayer, no accounts |
| Data format | **JSON** under `data/` (not `.tres`) — agents can read/edit/validate it without Godot tooling |
| Baseline UX | 1280×720 logical window, keyboard+mouse; UI scales from that |
| Art | Placeholder-first (colored shapes / free assets); replacement strategy documented only |

## Deliverables (files to create under `docs/`)

1. **`docs/00-OVERVIEW.md`** — Vision, pillars, tone, scope/phase table, glossary
   (CN/EN term pairs), doc map linking all other docs, the Doc Template and
   Vibe-Coding Conventions (below), Phase-1 demo-loop definition.
2. **`docs/10-DATA-SCHEMA.md`** — The contract everything else depends on:
   - JSON schemas with field types + full examples for: `Port`, `ShipType`,
     `Good`, `Officer`, `Nation`, `Discovery`, `Quest`, `Equipment`, `MapLegend`.
   - i18n rule: every display string is `{"zh": "...", "en": "..."}`; spec for a
     `validate_data.py` that checks schema conformance + both locales present +
     referential integrity (port.goods[] → Good ids, etc.).
   - Locked Phase-1 content lists (exhaustive, no open slots):
     - **30 ports**: Lisbon, Seville, Valencia, Barcelona, Marseille, Bordeaux,
       London, Amsterdam, Antwerp, Hamburg, Genoa, Naples, Palermo, Syracuse,
       Cagliari, Valetta (Malta), Venice, Ragusa, Athens, Candia, Cyprus,
       Smyrna, Istanbul, Beirut, Alexandria, Tripoli, Tunis, Algiers, Ceuta,
       Madeira.
     - **20 goods** (suggested set to finalize in doc): wheat, olive oil, wine,
       wool, cotton cloth, silk, spices, sugar, salt, dried fish, timber,
       iron, copper, glassware, leather, ceramics, perfume, carpet, amber,
       cheese.
     - **8 ship types** (suggested set): Latin, Sloop, Caravel, Galley,
       Brigantine, Nao, Carrack, Galleon.
     - **6 nations**: Portugal, Spain, England, Holland, Ottoman, Italy.
   - Harbor-relief fallback spec: when broke and shipless in port, an inn
     odd-job grants subsistence gold (prevents softlock per game-over rule).
   - ASCII-art map legend spec + tile-size/grid-size constants for the Phase-1
     map (documented here because combat/world docs reference it).
3. **`docs/20-WORLD-AND-SAILING.md`** — Tile-grid world model (TileMap layers,
   coordinate system, map file → runtime), 8-directional movement, game clock +
   day tick, speed formula, provisions/water per-crew consumption, daily wage
   deduction, morale model (provisions level + days at sea → morale tier),
   mutiny/desertion event spec, weather events, starvation/scurvy fail states
   (sea-death = game over), port discovery + entry/exit flow, minimap behavior.
4. **`docs/30-PORTS-AND-TRADE.md`** — Port facilities (market, shipyard, tavern,
   guild, palace, inn — each marked with the phase it activates), trade
   economy: base price, supply/demand modifier, price bands, per-port
   specialty goods, investment effects; buy/sell quantity maths; UI flows
   (screen-by-screen textual wireframes + exact interaction list).
5. **`docs/40-SHIPS-AND-FLEET.md`** — Ship stats (durability, capacity, speed,
   min/max crew, armament slots), purchase/repair/refit, fleet composition and
   flagship rules, cargo-hold maths (goods vs provisions vs armament share of
   capacity).
6. **`docs/50-CHARACTER-AND-PROGRESSION.md`** — Nationality choice flow (start
   port, starting ship/gold/reputation per nation), player stats
   (leadership/seamanship/combat/luck/etc.), XP/levels, officer recruitment +
   assignment to ship roles, per-nation reputation, harbor-relief odd-job
   flow (anti-softlock).
7. **`docs/60-COMBAT.md`** *(Phase 2)* — Turn-based grid-lite sea battles:
   grid setup from fleet composition, turn order, movement points, cannon
   range/arc/damage, ram, boarding trigger, captain duel on boarding
   (simplified best-of-N rounds), damage/surrender/capture/loot rules,
   retreat, AI behavior spec for enemy fleets.
8. **`docs/70-QUESTS-DISCOVERY-ENDGAME.md`** *(Phase 3)* — Guild quest types,
   royal missions + nobility-title ladder per nation, discovery/report system,
   piracy/bounty, tournaments, victory/retirement condition.
9. **`docs/80-UI-UX.md`** — Screen inventory per phase, navigation graph,
   keyboard/mouse scheme, dialog/text-box conventions, sailing HUD, save/load
   UX, placeholder-art palette + sizing grid.
10. **`docs/90-ARCHITECTURE.md`** — Godot project layout: directory tree, scene
    patterns, Autoload singletons (GameState, DataLoader, I18n, SaveSystem,
    EventBus), scene-vs-data split, versioned JSON save format with migration
    notes, "add new content = data-only change" rule, how the ASCII map files
    load into TileMap.
11. **`docs/IMPLEMENT-Phase1.md`**, **`IMPLEMENT-Phase2.md`**,
    **`IMPLEMENT-Phase3.md`** — Ordered, checkable task backlogs. Each task:
    goal, docs it draws from, files/scenes/data it creates, "done-when"
    acceptance criteria executable without human judgment where possible.
    Phase-1 backlog must end with the demo-loop acceptance scenario (below).
12. **`AGENTS.md`** (repo root) — Points agents at `docs/`, restates i18n and
    placeholder-art rules, gives doc-reading order. (Requires implementation
    mode — create as first step after plan approval.)

## Doc Template (mandatory skeleton for every system doc)

1. **Purpose & Phase** — what this doc specifies; which phase(s) it gates.
2. **Artifacts** — exact files/scenes/data keys this doc defines.
3. **Dependencies** — which docs must be read first.
4. **Systems/Mechanics** — each with concrete numbers and formulas, never
   adjectives (e.g., `price = base × (0.8 + 0.4·supplyFactor)`, clamp
   `[0.5×, 2×]`).
5. **Data Examples** — valid JSON, `zh` and `en` both filled.
6. **Edge Cases & Fail States** — enumerated explicitly.
7. **Acceptance Criteria** — checklist an agent can verify.

## Vibe-Coding Conventions (apply to all docs)

- Concrete numbers/formulas mandatory; no "TBD" — resolve inline or mark
  `OUT OF SCOPE (phase N)`.
- Every mechanic maps 1:1 to named artifacts (scene/script/data-key paths).
- All JSON examples must parse.
- Every CN string has an EN pair and vice versa; glossary covers both.

## Phase-1 Demo Loop (definition of "playable", to be encoded in
`00-OVERVIEW.md` and as the final acceptance scenario of `IMPLEMENT-Phase1.md`)

New game → pick nationality → start in home port with starter ship + gold →
buy goods at market → sail to another port on the tile-grid map consuming
provision/water per day → storm or supply fail state reachable → sell goods at
a profit affected by supply/demand → repair/refit at shipyard, recruit officer
at tavern → save → quit → load → state fully restored. All text toggleable
zh/en at runtime.

## Writing Order (task list)

1. `00-OVERVIEW.md` (conventions, template, demo-loop).
2. `10-DATA-SCHEMA.md` (foundation + locked content lists).
3. **User review gate A**: user checks decisions/content lists, then continue.
4. `90-ARCHITECTURE.md`.
5. `20-WORLD-AND-SAILING.md`, `30-PORTS-AND-TRADE.md`,
   `40-SHIPS-AND-FLEET.md`, `50-CHARACTER-AND-PROGRESSION.md`.
6. `80-UI-UX.md` (Phase-1 screens; later-phase screens marked).
7. `IMPLEMENT-Phase1.md` + gap audit: walk every Phase-1 task; any design
   question it raises gets answered back into docs 00/10/20/30/40/50/80/90.
8. **User review gate B**: user confirms Phase 1 is fully specified.
9. `60-COMBAT.md`, `70-QUESTS-DISCOVERY-ENDGAME.md`.
10. `IMPLEMENT-Phase2.md`, `IMPLEMENT-Phase3.md` (lettered lower-fidelity
    sections acceptable; mark deferred details as task-owned).
11. Cross-check pass: JSON parses; referenced files/docs exist; ports/goods in
    examples exist in content lists; every CN string has EN pair.
12. `AGENTS.md` (first implementation-mode step).

## Validation

- Docs are complete when every `IMPLEMENT-PhaseN.md` task is executable from
  the task text + referenced docs alone, with no design questions.
- JSON examples spot-checked with a parser during the writing session.
- Demo-loop scenario traceable end-to-end through Phase-1 docs with no gaps.

## Out of Scope

- Any game code, Godot scaffolding, real art assets.
- Balanced final numbers (first-pass values only).
- Multi-protagonist story campaigns.
- Audio design beyond a placeholder note in `80-UI-UX.md`.
- Full world map authoring (~100 ports) until Phase 3 tasks.

## Risks

- Tile-grid map authoring (Med + W Europe coastline as ASCII) is the biggest
  content workload in Phase 1 — mitigation: fixed grid size constant in
  `10-DATA-SCHEMA.md`, authored once, validated for port reachability (a
  validation step must confirm all 30 ports are sea-reachable from Lisbon).
- Doc bloat from full UW2 scope — mitigation: later-phase docs may defer
  detail into their `IMPLEMENT-PhaseN.md` tasks; user gates A/B stop overreach
  early.
- Divergence between docs during later phases — mitigation: doc map +
  dependency section in template; gap audits at steps 7 and 11.
- Morale/mutiny tuning can create unfair-feeling deaths — mitigation: doc
  must define morale tiers with explicit numeric thresholds and a warning
  HUD indicator before mutiny is possible.
