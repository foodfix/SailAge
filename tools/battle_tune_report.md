## Findings & deviations (recorded, master-owned)

- **Never writes game data** (correction 11): the learned integers land doc-first through the master's θ-finalization task (§4.9c amendment, then `ai_search.gd` const sync). This report is the tool's only output besides its state file.
- **θ-seat flee gate** (runner seam, documented in `battle_tune_runner.gd`): gate ① is enemy-seat-only (§4.8a correction 5 — player ships never auto-strike); gate ② for the T3 seat uses the hp% + morale clauses, and the `aggression < 25` clause stays on the T2 baseline seat. Rationale: every shipped `ai_level = 1` row already carries aggression ≥ 60 (clause inert for T3), and an always-on flee would pre-empt the search on every turn, leaving θ unobservable in the cautious stage.
- **Cautious-stage baseline profile**: the job's `baseline_side_profile` seam carries the navy hunter row (forced `ai_level: 0`) on the cautious stage. With the engine-default row on BOTH seats, every cautious battle is a no-contact stall (both sides flee-always) — no gradient, no behavior contrast. Swap B of the pair still rewards catching the runner; the merged objective therefore leans fight-y — read the distinctness gate with that in mind.
- The frozen table's `enemy_count` field is the band sample; the runner asserts the actual `compose_enemy` count against `kind_bands` instead (the §4.11.3 roll owns composition).
- `current.dir` was sampled beyond the slot spec's strength field so the §4.3a current modifier actually bites at strength > 0 (strength alone with an empty dir is a no-op in the engine).
- The baseline T2 is assembled from `AiFleet.decide`'s own static helpers (nothing copied) because the plain call dispatches into T3 for every `ai_level = 1` kind and is enemy-brained (it would self-target from the player seat).
